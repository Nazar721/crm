Перший огляд — `21cee04`; другий (закрив P1 + частково P2) — `e9d59c0`.

## Що зроблено

Сторінка `/settings` розкладена на 4 вкладки без зміни моделі даних,
сховища, експорту/імпорту й доменних дій:

- **Фінанси** — валюта відображення + редактор курсів (ті самі дії
  `setDisplayCurrency` / `saveRates`, що й на сторінці Фінанси;
  гарантія «курси не скидають валюту» збережена).
- **AI-помічник** — той самий `ProviderSettingsCard`, що й на
  `/assistant` (сховище `crm_assistant_provider`; ключ не зберігається
  в браузері й не потрапляє в копії; серверний ключ live-провайдерів
  налаштовується окремо).
- **Копії та імпорт** — експорт/імпорт/відновлення/інцидент/попередження,
  уся логіка лишилася на сторінці й передається пропсами.
- **Система** — стан збереження, лічильники, пошкоджені колекції, журнал
  (очищення журналу як і раніше не чіпає здоров'я даних).

Додано централізований реєстр `lib/settings-tabs.ts`, щоб пакет 05
(завдання/нагадування; історію змін додає пакет 03) додавав свої вкладки
в одному місці без паралельних правок сторінки.

## Виправлення за оглядом (поверх 21cee04)

- **P1 — форма AI більше не монтується з типовими значеннями.**
  `AssistantSettingsSection` читає сховище синхронно в lazy-ініціалізаторі
  (як `/assistant`), тож перший рендер показує збережений профіль
  (provider/model/demo/baseUrl). `ProviderSettingsCard` отримав dirty-гард:
  зовнішня синхронізація йде лише при зміні props І коли користувач не
  редагує; будь-який ручний ввід блокує автосинхронізацію до збереження;
  після збереження форма чиститься (включно з полем перевірки ключа —
  секрет у сховище не потрапляє й нікуди не переноситься).
- **P2 — вкладка відкривається через URL (доопрацьовано після другого огляду).**
  URL — єдине актуальне джерело вкладки після входу (`useSearchParams`,
  реактивно: mount, кліки, Back/Forward, внутрішні Next Link на той самий
  pathname з новим query — без ручних слухачів `popstate`). Відсутність `tab`
  і некоректний `tab` розрізняються: missing → fallback sessionStorage,
  invalid/empty → нормалізація до `finance`. Перший entry без `?tab=`
  канонізується через `router.replace` (fallback → визначений URL), тож Back
  повертає на вкладку, а не на адресу без стану; недійсний `?tab=` так само
  нормалізується через replace (історія не засмічується). sessionStorage —
  лише необов'язковий fallback першого entry (остання показана вкладка).
  Банер `StorageWriteBanner` веде на `/settings?tab=backup`. Клік — звичайна
  Next-навігація (`router.push`), модифікований клік (нова вкладка/вікно)
  лишається браузеру; `preventDefault` лише для звичайного кліку.
  `useSearchParams` загорнуто в `Suspense` (production build чистий).
  Недоступність sessionStorage/router не кидає — працює fallback.
- **P2 — перемикання вкладки не стирає незбережене.** Секції Фінанси/AI
  лишаються змонтованими (`hidden`, а не умовний рендер); чернетка курсів
  синхронізується через `syncRatesDraft` — чисті поля підтягують snapshot,
  брудні (редаговані) не затираються навіть коли поруч змінюється
  `displayCurrency`; є індикатор «Є незбережені зміни курсів».
- **Тексти:** «ключ не зберігається» уточнено (браузер/копії vs серверний
  ключ); прибрано заяву про «вже підключену» live-модель — написано
  перевірити чат перед робочими командами.

## Сценарії UI (для основного агента — повторити вручну)

- P1: зберегти в `/assistant` провайдер opencode + demo=true → відкрити
  `/settings?tab=assistant` → поля показують opencode/demo (не типові) →
  натиснути «Зберегти» без змін → профіль НЕ перезаписується типовим →
  перейти на `/assistant` → той самий профіль.
- P1-негативний: на вкладці AI змінити провайдера, НЕ зберігати →
  дочекатися будь-якого зовнішнього оновлення → ввід НЕ затерто.
- P2-1 (історія): вхід на `/settings` без tab при stored finance →
  URL канонізується до `/settings?tab=finance` → клік backup → URL
  `/settings?tab=backup` → Back повертає finance (а не «порожній URL з
  екраном backup») → Forward знову backup.
- P2-2 (invalid): `/settings?tab=hosting` і `/settings?tab=` при відкритій
  іншій вкладці → finance і канонізація URL через replace; відсутність
  `tab` (перехід з іншої сторінки) → fallback sessionStorage, потім replace.
- P2-3 (внутрішній перехід): з уже відкритого `/settings?tab=finance`
  перейти Next Link банера на `/settings?tab=backup` → відкривається backup
  без перезавантаження; клік по табу звичайний (модифікований клік — нова
  вкладка — працює стандартно).
- Без sessionStorage (нова вкладка/приватний режим): direct
  `/settings?tab=backup` → backup; `/settings` → finance.
- P2: у Фінансах ввести USD=47 без збереження → перейти на Систему →
  повернутися → «47» на місці + індикатор незбереженого; змінити
  displayCurrency → поле USD=47 НЕ затерто; ті самі переходи при
  Back/Forward не гублять чернетку (секції mounted).
- Десктоп 1440×900 і мобайл 390×844: 4 таби-посилання в ряд (чинні стилі
  `.tabs`/`.tab`), секції в 1–2 колонки через `.settings-grid`.
- Ручний клік-прохід у браузері в цьому середовищі **не виконувався** —
  лише збірка + тести (включно зі Suspense-межею в production build);
  це НЕ доказ повної UI-коректності.

- Дубль `COLLECTION_LABELS` між сторінкою (модалка імпорту) і секцією
  Системи — свідомо лишено, щоб не тягти спільний модуль у цьому пакеті;
  можна винести в пакеті 06 при узгодженні.
- `/assistant` лишає власну копію налаштувань провайдера (за ТЗ пакети не
  вимагають її прибирати; обидва місця пишуть в одне сховище).
- Редактор курсів на `/finance` не чіпався (єдине джерело дій спільне).
- Семантика `?tab=` (missing vs invalid) покрита чистими тестами та
  моделлю історії; реактивність `useSearchParams`/`router.push`/
  `router.replace` у реальному браузері не репродуковувалася в цьому
  середовищі — потрібна ручна перевірка за сценаріями P2-1…P2-3 вище.
