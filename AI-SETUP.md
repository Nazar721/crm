# AI-помічник: OpenRouter Free

Секрети OPENROUTER_API_KEY та OPENCODE_API_KEY збережено лише в локальному .env.local. Файл ігнорується Git. Для Vercel змінну потрібно додати окремо; деплой не виконаний.

## OpenRouter: фактична перевірка

Провайдер OpenRouter, модель openrouter/free, endpoint https://openrouter.ai/api/v1/chat/completions. Сервер дозволяє лише цей model ID або попередню MiMo Free; платні ID та openrouter/auto відхиляються до запиту. OpenRouter отримує provider.max_price {prompt:0,completion:0} і require_parameters:true для структурованої відповіді. Довільний endpoint з браузера не використовується.

Фактичний API-тест з новим ключем успішний: чернетка вигаданого клієнта (маршрутизатор обрав liquid/lfm-2.5-2.6b:free). Окремо зі спільними інструкціями отримано правильну чернетку вигаданого проєкту з клієнтом, бюджетом 10000 та myPercent 30. Одна попередня відповідь не збігалася з усіма очікуваними полями — якість різних безкоштовних моделей може відрізнятися, власник перевіряє чернетку. Жодних реальних даних у тестовий запит не відправлено й записів у CRM не створено. Повний шлях у браузері з сесією власника ще потрібно перевірити вручну: керування браузером недоступне.

У налаштуваннях сторінки обрати OpenRouter → Free Models Router, Demo вимкнути. Нові профілі мають цей вибір за замовчуванням; збережені раніше налаштування залишаються й змінюються через UI. Сервер перед чернеткою перевіряє обов’язкові поля; за відсутності повертає уточнення, після ручного редагування повторно перевіряє їх при підтвердженні.

Підпис чернетки використовує ASSISTANT_SIGNING_KEY, або OPENROUTER_API_KEY, або OPENCODE_API_KEY (у цьому порядку). Для однакових чернеток між інстансами Vercel значення має бути однакове на всіх інстансах. Зміна ключа робить старі чернетки недійсними. Підтвердження перевіряється незалежно від поточно обраного провайдера, без повторного звернення до моделі.

## Попередній провайдер OpenCode

Синтетичний запит до https://opencode.ai/zen/v1/chat/completions з моделлю mimo-v2.6-flash-free отримав HTTP 403, FreeTierError: "OpenCode's free tier can only be used from within OpenCode". Це обмеження прямого API для безкоштовного тарифу, а не встановлена помилка ключа. Жодних платних моделей, підміни клієнта або обходу обмеження не налаштовано. Це попередній недоступний варіант. Активне нове підключення — OpenRouter Free.

## Підготовлено й перевірено на синтетичних даних

Авторизація запиту перевіряється сервером через Supabase getUser; crm_read додатково перевіряє власника. До моделі не передаються API-ключі, токени, метадані та паролі. Контекст містить записи CRM і підсумки з тих самих формул, що дашборд. Дані користувача для реального тесту API не використовувалися.

Модель повертає текст, уточнення або одну чернетку. Дії обмежені явними схемами полів: клієнти, проєкти, фінанси, оплати, фахівці, партнери, борги, накопичення. Створення, редагування і видалення застосовуються тільки після натискання підтвердження. Конвертація, завершення проєкту і кілька дій за один запит поки через звичайні форми. Фінансові налаштування (курси, валюта відображення) також змінюються через чернетку. Спільні інструкції — ASSISTANT-INSTRUCTIONS.md і lib/assistant/instructions.ts. Звіти використовують надані записи; правильність пояснення моделі потребує звірки, модель не гарантує точних розрахунків для довільних питань.

Чернетка підписана сервером, прив’язана до користувача і стану всіх даних; строк 15 хвилин. Підтвердження повторно перевіряє підпис, поля й актуальність даних. Запис використовує спільні доменні дії та атомарний Supabase commit; повторна чернетка після зміни стану відхиляється. Перевірка стану відбувається всередині черги доменних дій, тому два одночасні підтвердження не створюють дублікат.

Оплата проєкту перевіряє суму, валюту рахунку, залишок бюджету; одним commit збільшує prepayment та додає пов’язаний income у фінанси. Сам проєкт не пересоздається, його таймер/клієнт/інші поля не змінюються. При відмові обидві колекції залишаються попередніми.

Є обмеження довжини команд і відповідей, таймаут 45 секунд, скасування очікування моделі. Локальний ліміт 12 запитів за хвилину і один активний запит на користувача не є глобальним розподіленим лімітом для всіх Vercel інстансів. Чернетки залишаються в пам’яті сторінки, історія чату у sessionStorage. Голос використовує браузерне розпізнавання: підтримку Safari/iPhone фактично ще не перевірено. Керування ключами різних провайдерів через CRM та захищене серверне сховище ключів ще не реалізовані.
