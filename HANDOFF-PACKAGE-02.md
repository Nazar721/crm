## Що зроблено

Кнопка «Копіювати» у завершених проєктах (усі розміри екранів — та сама таблиця з `data-label`) відкриває **ту саму форму створення** (`ProjectForm` з `project=null`) із заповненими умовами. До натискання «Зберегти» не створюється запис, ID, клієнт, платіж. Збереження йде через чинний `saveProject` → новий ID, запис додається до активних, оригінал недоторканий. AI використовує ту саму логіку через чернетку `projects/create` з полем `copyFromId`.

## Сценарії (що покрито тестами)

1. Копіювання заповненого завершеного проєкту → лише дозволені умови (allowlist, жодного зайвого ключа).
2. Оплати/виплати/прибуток/банк/усі старі дати скидаються; новий статус «Очікування оплати», старт = today(); новий ID.
3. Видалений клієнт/фахівець/партнер → `missing=true`, застарілі ID не підставляються, ручні дозволені поля збережені, 3 тексти попереджень.
4. `pickCopyOverrides` відкидає скинуті/службові/порожні поля.
5. AI-копія: модель намагається протягнути `prepayment/status/bank` → система скидає (оплата 0, статус «Очікування оплати», банку немає).
6. AI-копія: підготовка чернетки **не пише** в базу (`db.commits` не зростає).
7. AI-копія: підтвердження створює **рівно один** новий активний проєкт; оригінал у completed незмінний (deepEqual); той самий підписаний стан повторно не виконується.
8. Чиста функція не мутує вхід (оригінал зберігає значення).
9. Невідомий `copyFromId` → помилка «не знайдено».

## Що НЕ перевірено

- Живий AI-провайдер (план/виконання перевірені на синтетичній базі через фейковий datasource).

## Залишкові обмеження

- Форма копії — це форма СТВОРЕННЯ; частка від фахівця (`myPercent`) переноситься як умова, автоправило вимкнене при копії (показується явно, змінюється вручну). Правила частки не змінювались (згідно ТЗ).
- Копіювання доступне лише з завершених проєктів (кнопка саме там); активні не мають цієї кнопки.
