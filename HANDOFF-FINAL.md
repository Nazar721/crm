## Ревізія після спільного огляду 04–06 (`5c76eef`)

1. **P1 Доставка нагадувань.** Оркестрацію винесено в чистий модуль `lib/reminder-delivery.ts`: показується **вся пачка due** (без прихованого `slice(0,3)`), позначається **лише реально показане**; **прихована вкладка не споживає** нагадування; **in-flight gate** — проти одночасних interval/focus/visibility; збій показу одного не блокує решту; **збій позначки** (stale revision/конкурентна доставка) → без сліпого повтору, з callback синхронізації (`reloadStore`). Заявлена доставка — **лише in-app** (системні Notification зараз не створюються; пропозиція дозволу лише на вкладці «Нагадування», без имітації push). Push закритого застосунку — не в цьому пакеті. Тести: 7 сценаріїв оркестрації (`tests/reminder-delivery.test.ts`) + фільтр реально актуальних позначок.
2. **P2 Покриття хостингу.** `mergePeriods` зливає суміжні/перекривні періоди (кінець включний) перед розрахунком покриття та продовження: ланцюжок 01.01–31.01 + 01.02–31.12 → покриття до 31.12, пропозиція продовження з 01.01 наступного року (не з оплаченого часу); справжня прогалина не зливається; суто окрема майбутня оплата не дає покриття сьогодні. UI/AI використовують той самий модуль. Тести: ланцюжки/перекриття/хаос/прогалина/архів + репродукція огляду.
3. **P1/P2 Дати й нагадування.** `isValidTaskDate` — реальний календарний round-trip («30 лютого» → відмова); `isValidTaskTime` — 00:00–23:59; прямий `reminderAt` — лише ISO-інстант **з таймзоною**; `validateTaskInput` перевіряє `reminderDate/reminderTime` і відхиляє **неповну пару** (явна помилка, не мовчкивий clear); оновлення з лише одною частиною пари не прибирає чинне нагадування; AI `missingQuestions` уточнює час/дату при неповному нагадуванні; backup-валідатор завдань — ті самі строгі дати. `HostPaymentForm` за замовчуванням бере **Kyiv-«сьогодні»** (`kyivDateString`), не UTC-зріз (межа півночі Kyiv у тесті).
4. **P2 SQL-гейт.** `npm run test:sql` запускає **всі** `*.test-dist/tests/*-sql.test.js` (зараз: `history-sql` 001+003 і `hosting-sql` 001+003+004+005); відсутність runtime, файлів або будь-який FAIL → exit 1 (skip ≠ PASS).

## Ревізія 2 після повторного огляду (`3e019be`)

1. **P2 Форма не ховає неповне нагадування.** Payload форми винесено в чисту функцію `buildTaskSavePayload` (`lib/tasks.ts`), яку викликає `TaskForm.handleSave`: **введені** `reminderDate/reminderTime` передаються відкрито (неповна пара потрапляє до спільного `validateTaskInput` і дає **видиму помилку**; діалог лишається відкритим, `onSave` не викликається — раніше spread мовчки відкидав дату без часу і «рятунок» був несправедливий). Обидва порожні поля — чинне нагадування зберігається; явний `reminderClear` працює. Регресія саме для payload/handleSave форми (+ неможливий стінний час у формі), не лише прямих actions. Реальний браузерний прохід НЕ виконувався.
2. **P2 Строгий ISO/DST.** `isIsoInstant` тепер перевіряє реальну календарну частину («30 лютого» → false), години/хвилини 00–23/00–59 і зсув ≤±14:00 **перед** `Date.parse`; backup-валідатор використовує його для `reminderAt/reminderShownAt`. `validateTaskInput` для **повної** пари дата+час вимагає успіху `kyivDateTimeToIso` (весняна прогалина Kyiv, 28.03.2027 03:30 → явна відмова, не мовчкивий пропуск) — для нагадування і для дедлайну; `_saveTask` перевіряє ефективну пару при частковому оновленні (наявний дедлайн + новий час). Політика наявних/імпортованих даних: неможливий стінний час → день без часу з попередженням (час не вигадується). Позитиви: 29.02 у високосний, звичайні моменти. Тести: відсутність запису/зміни стану після відмови.

## Що готово лише локально / що потребує сервера

- **Готово локально:** увесь код, тести, синтетичні перевірки, SQL-файли як файли; локальний режим CRM (localStorage) працює повністю (журнал + скасування + відновлення інцидентів).
- **Потребує основного агента:** застосування SQL-міграцій 003→004→005 на контрольованій/production базі (за порядком вище), перевірка owner isolation і реальних RPC на живій Supabase, ручний UI-прохід (ноутбук + вузький екран: `/hosting`, `/tasks`, вкладки налаштувань), push і публікація точного коміта `f7cfd8c`.

## Відомі обмеження

- **Доставка нагадувань:** канала два — (1) in-app показ у відкритому застосунку (**реалізований**: оркестрація `lib/reminder-delivery.ts` + стійка позначка `reminderShownAt`, узгоджувана між пристроями через колекцію; збій позначки → синхронізація стану без сліпого повтору) і (2) системні Browser Notification — **дозвіл можна надати на вкладці «Нагадування», але фактичний new Notification/worker-delivery у коді НЕ реалізовано** (пропозиція не імітує доставку; push при закритому застосунку/заблокованому iPhone — окрема наступна інтеграція, не обіцяється). Виконані/скасовані/показані/перенесені нагадування не доставляються старим сповіщенням (перевірено тестами оркестрації).
- Завдання одноразові (без автоматичних повторень); прив’язка до проєкту/клієнта — майбутнє розширення. Фізичне видалення карток хостингу в v1 не пропонується (архів). Оплата клієнта/маржа — окремо після уточнення потреби.
- Формат експорту — **v3** (хостинг + завдання як опціональні колекції зі збереженням поточних даних при імпорті старих копій); версії не розділяються між 04/05 — один формат.
- AI-контекст обмежений (tasks ≤200, hosting ≤200/300, чесні прапорці обрізання); «я додав» від моделі ніколи не є фактом запису — лише підтверджена чернетка.
- Локальний журнал: атомарності між даними та журналом у localStorage немає (задокументовано): recovery-мітка + видимий інцидент + блок запису після непідтвердженого відкату.
