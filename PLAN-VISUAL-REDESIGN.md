# План: візуальне оновлення WebCRM («Графітова робоча панель»)

База: `6a8f9db`, гілка `stage2-supabase`, робоче дерево чисте.
Межі: без SQL, без нових бізнес-функцій, без змін фінансових формул, без нових важких бібліотек.

> **Статус.** Ітерація 1 (етапи A–F) зібрана, але **відхилена власником** за композицією
> (верхній ряд, три окремі картки, ряди обведених прямокутників) і за «надто тьмяною»
> палітрою. Поточна композиція головної та палітра описані в **§6 «Ітерація 2»** —
> саме вона є чинною. §1 (mapping джерел даних) і §2 (токени) лишаються актуальними
> в частині **джерел даних і заборон**; конкретні значення токенів див. §6.2.

Додатково (не входить у 15, але вимагає ТЗ §3.3): **«Мій дохід від агенції за місяць»** =
`incomeForMonth(snapshot, currentMonth).agencyIncome` — уже обчислюється сьогодні як `data.cmIncome`
і показується в модалці. Відкриває чинну модалку з `AgencyIncomeChart`.

**Семантику не змішувати** (ТЗ §4): `month-income` (фінанси) ≠ `agencyIncome` (частка агенції) ≠
`closedCollected` (оплати завершених) ≠ `netProfit` (чистий прибуток). Жодних сум між ними.

## 2. Дизайн-токени та база стилів

**Файл:** `app/globals.css` (секція `:root`, рядки ~128–190).

- Додати/перейменувати на семантичні `--g-*`: поверхні `#101014/#15151B/#1B1B23/#24242E`,
  межа `#34343F`, функціональна межа `#646C74`, текст `#F5F5F7/#ACACBB`, акцент `#FF8156` +
  `--g-accent-ink #21130D`, дохід `#65D6A1`, витрата `#F48891`, попередження `#E8BD69`.
- Існуючі імена, які використовують усі сторінки (`--accent-green`, `--danger`, `--text-primary`,
  `--text-secondary`, `--bg-*`, `--border`, `--radius-*`), перенаправити на нові значення, щоб
  статуси/суми/межі перефарбувались по всій CRM без правки кожного селектора.
- `--transition: 0.28s cubic-bezier(0.32,0.72,0,1)` → `--ease: cubic-bezier(.2,.8,.2,1)`,
  `--t-fast: 120ms`, `--t-med: 160ms`, `--t-slow: 200ms`.
- Радіуси: картки 16–20, кнопки 10–12, pill лише для справжніх перемикачів/бейджів.
- Типографіка: системний стек (нові шрифти не завантажувати). Заголовки сторінки 28/24 px,
  блоків 17/16, текст 15/14, другорядний 13/12. `font-variant-numeric: tabular-nums` на сумах
  і числових клітинках; `white-space: nowrap` + `overflow-wrap: anywhere` для сум.
- Прибрати надлишок: `backdrop-filter` (~18 місць), `::before/::after`-блиск на
  `.stat-card/.chart-card/.modal/.sidebar/.tabbar/.settings-card/.developer-card/.btn-primary`,
  декоративні `.orb*` (разом із розміткою в `app/layout.tsx:49-55`), `navGlow`/`badgePulse` keyframes.
- `transition: all` (рядки 360, 431, 498, 697, 986, 1061, 1084) → конкретні властивості
  `background-color, border-color, color, transform, opacity`.
- Анімації за ТЗ §7: `fadeIn` сторінки 400ms → 180ms; `cardIn`/`chartReveal` → новий
  `ov-enter` (opacity + translateY 5px, 180ms); `modalBounce` → fade + scale 0.98→1, 180ms;
  `sheetUp/Down` 300ms → 200ms, без пружини. Прогрес `progressFill` — без скролу цифр (суми
  показувати одразу).
- `@media (prefers-reduced-motion: reduce)` — розширити: прибрати transform/scale/stagger,
  анімації графіків (`ChartJS.defaults.animation.duration = 0` через `ChartSetup`),
  залишити функціональність.

## 3. Етапи робіт

### Етап A — токени та знадоба (коміт `style(tokens)`)

1. Базові гейти **до** змін: `npm run typecheck`, `npm run lint`, `npm run test`,
   `npm run test:sql`, `npm run build` — зафіксувати результати як baseline (включно зі
   старими warning; нові не маскувати під старі і навпаки).
2. Заміна `:root`-токенів + моти-секція + чистка glow/glass/orb (див. §2).
3. `app/layout.tsx` — прибрати `.orb-bg` розмітку.
4. Тест `tests/design-tokens.test.ts`: контраст ключових пар (AA/3:1), наявність
   `prefers-reduced-motion`, відсутність `transition: all` у новій секції.
   *Це тести на інваріанти ризику (контраст/доступність), не на сам CSS.*

### Етап B — оболонка (коміт `style(shell)`)

- `components/layout/Sidebar.tsx`: підпис `Dashboard` → **`Огляд`**; ширина 224–240px
  (`--sidebar-width`); групи «Головна / Агенція / Фінанси / AI» + «Налаштування» у футері;
  іконки 18–20px; активний пункт = стримана поверхня `--g-elevated` + 2px акцент зліва
  (без glow, без pill). Нічого не дублювати у верхніх вкладках.
- Вузький desktop (768–1024px): бічна панель стає drawer (overlay + Escape/повернення фокуса),
  а не стискає контент.
- `components/layout/TabBar.tsx`: `Дашборд` → `Огляд`; активний пункт без світіння;
  `padding-bottom: env(safe-area-inset-bottom)`; аркуш «Більше» — фокус на перший пункт,
  Escape/клік поза межами → закриття, повернення фокуса на кнопку «Більше», `role="dialog"`.
  П'ять основних слотів зберігаються (4 посилання + «Більше»).
- `components/ui/Modal.tsx`: додати focus trap, `role="dialog" aria-modal="true"`,
  `aria-labelledby` на заголовок, збереження й повернення фокуса, інерційний скрол body.
  Escape вже працює. Структура header/body/footer залишається.

### Етап C — нова головна (коміт `feat(dashboard)`)

**Композиція (desktop):**

```
Огляд · дата (Europe/Kyiv, uk-UA)
[ Баланс + рахунки 40% ][ Рух коштів: графік 60% ]
Агенція
[ Дохід агенції ][ Активні ][ Борг клієнтів ][ До виплати ]
[ Компактні показники — 8 ячеєк, 4 у ряд ]
[ Аналітика завершених проєктів ][ Джерела клієнтів ]
[ Відкладення та цілі ][ Особисті борги ]
```

**Mobile:** баланс → рахунки → рух коштів → агенція (2×2) → показники по 2 →
аналітика → джерела → відкладення → особисті борги.

**Файли:**
- `lib/dashboard-view.ts` — **новий чистий view-model без React і без візуальних компонентів**.
  Обчислює все те саме, що сьогодні розкидано по `page.tsx` (останні 12 місяців, `md`,
  рахунки, джерела, цілі, агенційні місяці), викликаючи лише чинні
  `dashboardStats / bankBalances / savingsSummary / incomeForMonth / toDisplay /
  bankAmountToDisplay / project`. Фінансова логіка сюди **не переноситься** — лише агрегація
  підготовчих даних, яка вже є в сторінці.
- `lib/calc.ts` — додати **одну** чисту функцію `bankNativeBalances()` (суми рахунків у їхній
  власній валюті: `250 USDT`), із тими самими правилами `hidden`/`transfer`, що й
  `bankBalances()`. `bankBalances()` не змінюється. Гарантія — юніт-тест:
  `native[b] × rate(b) ≡ bankBalances()[b]` (допуск 1e-6) на фікстурі. Це потрібно, бо ТЗ
  вимагає не змішувати початкову валюту з еквівалентом (`250 USDT` окремо від `≈ 11 250 UAH`).
- `components/dashboard/` — компоненти за змістом:
  `BalanceCard`, `CashFlowCard`, `AgencySection`, `CompactMetrics`,
  `CompletedProjectsPanel`, `SourcesPanel`, `SavingsGoalsPanel`, `PersonalDebtsPanel`.
- `app/dashboard/page.tsx` — композиція + **scoped-класи `ov-*`** у власній секції
  `globals.css`. Глобальні `.stat-card/.tab/.page` на цьому етапі **не** чіпаємо.
- Графіки: `next/dynamic({ ssr: false })` зберігаємо; «Рух коштів» монтується одразу,
  приховані (графік активів, графік відкладень, модалка агенції) — за потреби,
  після показу коректно визначають розмір. Нові `options/data` мемоізуються, щоб не
  перестворюватись на кожному введенні.

**Рішення щодо розміщення:**
- Картка «Рух коштів» отримує текстовий підсумок (ТЗ §6): «Останні 12 місяців · Надходження X ·
  Витрати Y · поточний місяць неповний».
- «Дохід у фінансах (за місяць)» (`month-income`) живе в компактному блоці, а не в агенції —
  щоб не змішувати з «Моїм доходом від агенції».
- Компактний блок = 8 ячеєк: Загальний бюджет, Чистий прибуток, Дохід у фінансах (за місяць),
  Середній чек, Завершені проєкти, Клієнти, Фахівці, Партнери. Desktop 4 у ряд, mobile 2.
- Картка «Баланс»: сума 36–44px desktop / 30–36px mobile, делікатний помаранчевий градієнт
  лише в цій зоні; рахунки: `250 USDT` + окремо `≈ 11 250 UAH`; нульові — за «Усі рахунки»;
  кнопки «Відкрити фінанси» і «Графік активів».
- «Відкладення»: головна сума + прогрес + усі рядки цілів (scroll/«Показати всі»), не обмежувати
  трьома. «Особисті борги»: «Мені винні / Я винен» → `/debts`.

### Етап D — перенесення на решту CRM (коміт `style(pages)`)

Після узгодження композиції головної. Спільні клієнти токенів перефарбовуються автоматично;
додатково за потреби:

- **Таблиці**: рядки 48–56px, чіткі заголовки, спокійні роздільники, послідовні суми
  (`tabular-nums`) і бейджі; `search-wrap`/`filter-select` — єдина висота й вирівнювання.
  Мобільний режим «картка в рядку» (наявний) — 3–4 атрибути зверху, решта через розкриття.
- **Форми** (`components/forms/*`): групи полів, стабільні label/help/error, одна primary-дія.
  Зберегти валідацію, dirty-чернетки, блок повторного збереження; після помилки форма не
  закривається.
- **Модалки/ConfirmModal**: спільна структура, незалежний скрол body, мобільний аркуш із `dvh`
  + safe-area, focus trap/Escape/повернення фокуса (з Етапа B).
- **`app/settings/page.tsx`**: URL-вкладки, Back/Forward, чернетки — не чіпати логіку;
  на телефоні наявна сітка 2 колонки без обрізання, без повернення старого горизонтального рядка.
- **`components/assistant/*`**: спокійні бульбашки, Markdown/таблиці з горизонтальним скролом
  лише всередині повідомлення (`.ai-table-scroll`), редактор + send/stop в одному адаптивному
  блоці, чернетки й підтвердження залишаються виразними й редагованими.
- **Графіки**: одна система кольорів (акцент = ключова серія, зелений = дохід, сірий = база),
  читабельні осі, мінімум сітки, порожній стан без вигаданих даних, текстовий підсумок.
- **Системні банери** (`.write-block-banner`): у потоці сторінки, без перекриття header/контенту.
- **Вхід** (`components/CloudAccess.tsx`): ті самі токени, 16px поля.
- `app/globals.css` — старі стилі замінювати поступово; видаляти лише підтверджено невикористане;
  не накопичувати черговий шар mobile-override у кінці файлу.

### Етап E — анімації, доступність, продуктивність (коміт `fix(a11y-motion-perf)`)

- Таблиця ТЗ §7 дотримана; easing `cubic-bezier(.2,.8,.2,1)`; бюджет входу ≤250ms;
  без stagger для 15 карток, без скролу цифр, без fade-out між маршрутами.
- Анімувати лише `transform/opacity`; `prefers-reduced-motion` вимикає рух/масштаб/stagger/графіки.
- Touch цілі ≥44×44, desktop іконкові дії ≥36×36; видимий focus; інтерактивні картки —
  `<Link>`/`<button>`, не `div onClick`; вкладки — узгоджений патерн (tablist **або**
  посилання з коректною семантикою), без зайвих ARIA-ролей.
- Ховер не застосовувати до неклікабельної статистики.

### Етап F — перевірки, скриншоти, handoff (коміт `docs(handoff)`)

**Гейти:** `typecheck`, `lint`, `test`, `test:sql`, `build` — усі успішні.

**Порівняння до/після на одному snapshot:**

**Виміряти й записати:**
- Bundle: First Load JS маршруту `/dashboard` з `next build` до/після (однакова одиниця —
  gzip-звіт Next). Поріг: без нових animation/UI-бібліотек і без необґрунтованого приросту

  long tasks >50 ms від анімацій не має бути; наявні проблеми відокремити від внесених.
